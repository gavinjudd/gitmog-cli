# Git Mog v0.5.0 — Frictionless Sign-In and Terminal Interaction Polish

Git Mog v0.5.0 makes the first run shorter and GitHub authorization easier without changing the
public battle. After an explicit sign-in choice, Git Mog opens the exact reviewed GitHub page in
the default browser. Enter opens it again while authorization continues, and the manual link
remains available. `--no-open` and `GITMOG_NO_BROWSER=1` keep the flow fully manual.

Private Context setup can now continue inside the same command. Git Mog can open the reviewed app
installation or settings page, recheck a selected-repository installation, continue public-only,
or cancel cleanly. Public and private authorization remain separate. Installation identifiers,
private repository names, tokens, device codes, and private source do not enter durable output.

The ordinary help, rate-limit choice, authorization prompts, errors, result hierarchy, Code
Quality sample wording, Private Context wording, and terminal color now prioritize the action and
visible facts. Code samples use readable file counts rather than percentages that could be
mistaken for whole-repository coverage. Technical contracts remain available in `--details`,
`--receipts`, and JSON. The meme engine keeps its evidence-backed authored corpus and unchanged
version; a deterministic 25-fixture editorial matrix now guards its visible output.

Automatic opening is one narrow, reviewed subprocess capability. Only the GitHub device page,
the exact Git Mog Private Context installation page, and a numeric GitHub installation-settings
path returned by the reviewed flow can launch. The fixed platform commands use no shell, no
arbitrary command string, no environment-selected browser, and no runtime dependency.

The public score, winner, rounds, verdict, coverage, evidence, battle key, request-plan identity,
and cache identity did not change. Private Context remains outside the public score with
`scoreInfluence: 0`, `publicWinnerInfluence: 0`, and `persisted: false`. Quality Judge remains
informational with `scoreInfluence: 0`. Target code is never executed, private source is never
stored, zero runtime dependencies remain, and v0.4.1 remains available.
