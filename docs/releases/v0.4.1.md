# Git Mog v0.4.1 — Private Context Receipt Closure and Terminal Polish

Git Mog v0.4.1 is a presentation-only patch over v0.4.0. Public-only remains the default, Private
Context remains explicit and additive, and the public score, winner, margin, rounds, verdict,
coverage, evidence, finishing move, Code DNA, Code Quality Preview, request identity, and battle
key remain invariant.

Default Private Context output now states complete source-free aggregates without unresolved `P`
markers. `--receipts` adds a separately labeled `PRIVATE AGGREGATES` section that contains only
aggregate facts and remains distinct from publicly checkable receipts. Ordinary terminal, card,
share, HTML, and SVG surfaces describe the bounded code-quality sample with repository count,
parsed-file count, and supported coverage instead of a numeric private preview score. `--details`
and structured JSON retain the unchanged score and label it selected-sample, informational,
non-scoring, non-winning, and non-persisted.

The shared progress renderer now clears the transient line and restores terminal state before
authorization instructions, choices, errors, cancellation, timeout, and final output. Explicit
two-flow runs identify public API capacity as step 1 and selected-repository Private Context as
step 2. Singular and plural output uses one deterministic grammar contract, and an empty
sustained-maintenance aggregate is neutral rather than a red weakness.

Quality Judge remains informational with `scoreInfluence: 0`. The GitHub App remains read-only,
selected-repository-only, and memory-only for authorization; private source and identifiers remain
process-only.
