# Git Mog v0.3.1 — Quality Policy and Request Accounting

Git Mog v0.3.1 keeps `CODE QUALITY · PREVIEW` visible and separate from the battle score. The
public compatibility fields remain `activation: "preview-only"` and `scoreInfluence: 0`; Quality
Judge cannot change the canonical score, score coverage, rounds, winner, margin, verdict, battle
key, evidence, or existing battle bytes.

The unused external reviewer proposal is retired. A fail-closed, human-readable policy now records
that Quality Judge is informational-only, and deterministic engineering validation covers parser
invariance, supported defects, coverage degradation, source safety, and canonical isolation.
Contributors can continue to submit reduced synthetic false-positive, false-negative, and parser
fixtures through the public issue forms.

Quality request planning is now separate from current-invocation telemetry. Actual source and
attribution calls, cache hits, and whole-result hits do not enter result identity or findings. A
whole-result cache hit reports zero current requests, old cache schemas fail closed, and cold,
warm, refresh, and no-cache executions retain identical findings and result identity for identical
evidence and caps.

The CLI request benchmark now derives the package version from the distribution manifest and
reconciles canonical requests, quality-source requests, attribution requests, allowance reads,
cache hits, and total observed fetches. Planned opportunity is reported separately from actual
calls; wall-clock values remain informational.

The release also updates reviewed full-SHA GitHub Actions pins, Vitest 4.1.11, ESLint 10.9.0,
Rolldown 1.2.5, and globals 17.11.0. Node 24 types remain intentional. The packed runtime remains
zero-dependency with no install lifecycle, native addon, runtime download, source map, workspace
import, model code, or machine path. TypeScript and JavaScript remain the only supported parser
lanes.
